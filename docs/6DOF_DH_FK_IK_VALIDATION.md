# Strict 6-DOF DH / FK / IK Validation Report

**Audit date:** 2026-09-05  
**Robot audited:** `skeleton_6R` / Skeleton 6R  
**Model:** Generic 6-DOF, six-revolute-joint serial chain  
**Implementation:** Standard Denavit-Hartenberg convention

## 1. Scope and conclusion

Fifteen fixed, manually selected joint configurations were evaluated. Each case was checked in both directions:

1. **FK:** the application FK result was compared element-by-element with an independent Standard-DH implementation.
2. **IK:** the target pose was generated by the independent implementation, passed to the application IK pipeline without supplying the answer as an initial guess, and the returned joint vector was verified again through independent FK residuals.

### Result

| Check | Cases | Passed | Failed | Failure rate |
|---|---:|---:|---:|---:|
| FK matrix comparison | 15 | 15 | 0 | **0.00%** |
| IK position + orientation residual | 15 | 15 | 0 | **0.00%** |
| IK joint-limit validity | 15 | 15 | 0 | **0.00%** |

The implementation is correct for this 15-case audit at the stated tolerances. This is strong evidence for the selected model; it is not a mathematical proof for every possible pose, especially arbitrary singular or unreachable targets.

For a revolute joint, the evaluated angle is:

\[

\[
d_i = d_{i,0} + q_i + \text{offset}_i
\]

The audited robot has no prismatic joints and all offsets are zero.

## 3. DH convention and FK equation

The application uses the Standard-DH transform:

\[
A_i = R_z(\theta_i)T_z(d_i)T_x(a_i)R_x(\alpha_i)
\]

Explicitly:

\[
A_i =
\begin{bmatrix}
c_\theta & -s_\theta c_\alpha & s_\theta s_\alpha & a c_\theta\\
s_\theta & c_\theta c_\alpha & -c_\theta s_\alpha & a s_\theta\\
0 & s_\alpha & c_\alpha & d\\
0 & 0 & 0 & 1
\end{bmatrix}
\]

The end-effector transform is:

\[
T_{06}=A_1A_2A_3A_4A_5A_6
\]

The independent audit implementation used this equation directly with separate 4×4 multiplication code. It did not call the application DH or FK functions to produce the reference pose.

## 4. IK validation method

For each case, the independent FK transform was used as the target. The application `solveIK` pipeline was called with no answer-based `initialGuess` and no answer-based `currentJoints`. The pipeline selected the analytical spherical-wrist solver for this robot and validated returned solutions through FK.

Strict acceptance limits were:

- Position residual: **< 0.0001 m** (0.1 mm)
- Orientation residual: **< 0.001 rad** (about 0.057°)
- Every joint inside its declared limit
- All residuals finite; no NaN or Infinity

Different IK branches can represent the same pose. Therefore, a returned joint vector was judged by pose residual and limits, not by equality with the original input vector.

## 6. DH table editor change

The canonical `skeleton_6R.json` DH values were not numerically changed because the independent audit found no geometry error.

The DH editor export logic was corrected in `src/features/dh/DHTableStudio.tsx`:

- CSV now exports evaluated θ and d values, including the stored constant and offset.
- LaTeX now exports the same evaluated θ and d values.
- Both exports use the shared `evaluateJointDH` implementation, keeping export behavior consistent with FK.
- SI and deg/mm conversions remain applied after evaluation.

This fixes the prior mismatch where a nonzero revolute `theta` constant or offset was omitted from exported active values, and where a prismatic base `d` or offset was omitted.
